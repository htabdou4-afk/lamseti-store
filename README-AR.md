# LAMSETI | متجر الدفاتر المخصصة وبطاقات الأعمال

متجر عربي باتجاه RTL لعرض المنتجات واستقبال طلبات الدفاتر المصممة حسب الطلب وبطاقات الأعمال، مع لوحة إدارة خاصة بالمالك.

## روابط المشروع
- المتجر المنشور: https://lamseti-store.vercel.app/
- مستودع GitHub: https://github.com/htabdou4-afk/lamseti-store

## التقنيات
- واجهة ثابتة: HTML وCSS وJavaScript.
- قاعدة البيانات والمصادقة وتخزين الصور: Supabase.
- الاستضافة والنشر التلقائي: Vercel.
- الخط: IBM Plex Sans Arabic.

## ملفات المشروع
- `index.html`: أقسام المتجر والنماذج ولوحة المالك.
- `styles.css`: الهوية البصرية والتصميم المتجاوب.
- `app.js`: المنتجات والسلة والطلبات وتسجيل دخول المالك.
- `config.js`: رابط Supabase والمفتاح العام publishable.
- `assets/`: شعار المتجر ورسمة الواجهة الرئيسية.
- صور المنتجات (`pink-notebook.jpg` وغيرها): موجودة في جذر المستودع.
- `schema.sql`: ملف المخطط الأصلي إن كان موجوداً في المستودع.

## وظائف المتجر
- عرض المنتجات المنشورة من قاعدة البيانات.
- سلة مشتريات وتسجيل بيانات التوصيل.
- طلب دفتر مخصص بمواصفات تفصيلية.
- طلب عرض سعر لبطاقات الأعمال.
- لوحة مالك لإضافة المنتجات وتعديلها وحذفها وإخفائها.
- رفع صور المنتجات إلى مخزن Supabase.
- متابعة الطلبات وتحديث حالاتها.
- تعديل اسم المتجر ورقم واتساب وملاحظات التوصيل.

## إعداد الاتصال والأمان
1. يستخدم المتصفح مفتاح Supabase العام من نوع publishable فقط.
2. لا تضع أبداً مفتاح `secret` أو `service_role` في ملفات الواجهة أو GitHub.
3. يجب أن تكون سياسات Row Level Security (RLS) مفعّلة ومضبوطة على جداول المنتجات والطلبات والملفات.
4. يجب أن يملك حساب المالك سجلاً في `public.profiles` بدور `admin`.
5. لا تفعّل التسجيل العام لحسابات الإدارة.
6. إذا سبق نشر مفتاح سري في محادثة أو مستودع، ألغِه وولّد مفتاحاً جديداً من Supabase.

## تحديث أمان الطلبات (مهم)
أضيف تحقق خادمي لطلبات السلة والطلبات المخصصة حتى لا يثق المتجر في أسعار يرسلها المتصفح. لتفعيله على قاعدة Supabase الحالية، افتح SQL Editor ونفّذ محتوى الملف:
`supabase/migrations/20261120_validate_lamseti_orders.sql`

هذا التحديث يجعل قاعدة البيانات تعيد قراءة سعر المنتج المنشور وتحسب إجمالي السلة بنفسها، وترفض المنتجات غير المتاحة والكميات غير الصحيحة. تحديث `schema.sql` وحده لا يغيّر قاعدة البيانات القائمة حتى تنفّذ الترحيل أعلاه. لم يتم تنفيذ هذا SQL على مشروع Supabase من داخل هذه المراجعة.

## قائمة التحقق قبل الإطلاق التجاري
- [ ] إضافة المنتجات الحقيقية وصورها وأسعارها.
- [ ] ضبط رقم واتساب الدولي في لوحة المالك بصيغة `213` متبوعاً بالرقم دون الصفر الأول ودون مسافات.
- [ ] اختبار إرسال طلب من السلة.
- [ ] اختبار طلب دفتر مخصص.
- [ ] اختبار طلب بطاقات الأعمال.
- [ ] التأكد من ظهور الطلبات في لوحة المالك ومن إمكانية تحديث حالتها.
- [ ] اختبار الموقع على هاتف وشاشة حاسوب.
- [ ] تحديد أسعار التوصيل ومناطق الخدمة وسياسة الاستبدال والإلغاء.
- [ ] إضافة سياسة خصوصية وشروط بيع واضحة قبل استقبال بيانات الزبائن على نطاق واسع.

## حدود النسخة الحالية
- لا يوجد دفع إلكتروني مدمج.
- لا يوجد ربط آلي مع شركات التوصيل أو حساب رسوم الشحن.
- تأكيد السعر ومدة الإنجاز والتوصيل يتم يدوياً مع الزبون.
- يجب إجراء اختبارات الطلبات والإدارة قبل اعتبار المتجر جاهزاً للبيع.
